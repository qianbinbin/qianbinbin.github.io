    Homebrew 使用中的一些问题

    2023-03-31 • 更新于 2026-06-14

    对于 Homebrew 用户，我只想说：如果不追求最新 macOS，请尽快转投 MacPorts。那是一个更符合 UNIX 哲学、速度堪比 Linux 的包管理器，它甚至支持 Mac OS X 10.6 “Snow Leopard” 的预编译二进制文件（除了那些需要更新工具链的包），简直是业界良心。

    现在的 Homebrew 真把自己当成第一方了。不尊重用户习惯，默认不信任第三方 tap，连没有签名的 cask 都要移除。

    我目前使用它的唯一用途是自定义 tap/formula/cask。

    No Cask quarantine support available: Swift runtime error 或 listxattr for destination failed: 2

    遇到这个问题，首先要确定 CommandLineTools 是否安装了正确版本，查看 brew doctor 的提示。

    如果安装正确，有可能是使用 OCLP 安装 Sequoia 导致，传递给 Swift 脚本的参数不正确，受影响的包括：

    /usr/local/Homebrew/Library/Homebrew/cask/utils/copy-xattrs.swift
/usr/local/Homebrew/Library/Homebrew/cask/utils/quarantine.swift
/usr/local/Homebrew/Library/Homebrew/cask/utils/trash.swift

    以我个人使用经验，这不仅影响安装 Cask，还会导致卸载 Cask 时 CommandLineTools 莫名其妙损坏。

    解决方案见此讨论，但他的仓库中使用了不换行空格 U+00A0，会导致 Swift 报错。我替换为常规空格并提了 PR，还没合并。

    以下是可以直接使用的 patch：

    curl -fsSL https://qianbinbin.github.io/posts/some-issues-when-using-homebrew/homebrew-oclp.patch | git -C $(brew --repository) apply

    该 patch 在 Homebrew 最新版可能无法使用，可使用 https://github.com/ajorpheus/homebrew-oclp-patches/pull/2。

    2026-06-14 重要补充：

    新版 Homebrew 不会再自动 pop stash 了，所做的修改会在 brew update 后失效。查看 $(brew --repository)/Library/Homebrew/cmd/update.sh，发现一个文档里不写的环境变量 HOMEBREW_NO_UPDATE_CLEANUP，将其设置为 1。

    download.clf.jetbrains.com.cn 证书不受信任

    安装 JetBrains 家的 3A 大作时，例如 pycharm-ce，会从 download.jetbrains.com 下载，从国内访问会重定向到 download.clf.jetbrains.com.cn，然后重定向到 download-cdn.jetbrains.com.cn。

    问题是如果使用 brew 版 curl（通过环境变量 HOMEBREW_FORCE_BREWED_CURL=1），download.clf.jetbrains.com.cn 的证书链不受信任：

    curl: (60) SSL certificate problem: unable to get local issuer certificate
More details here: https://curl.se/docs/sslcerts.html

curl failed to verify the legitimacy of the server and therefore could not
establish a secure connection to it. To learn more about this situation and
how to fix it, please visit the webpage mentioned above.

    原因是 download.clf.jetbrains.com.cn 使用了 Cloudflare 服务，证书链最终依赖的根证书颁发机构 AAA Certificate Services 在 2025 年四月被 Mozilla 移除，而 Mozilla 又被多个下游使用，如 ca-certificates、curl、certifi 等。具体可以运行 openssl s_client -connect download.clf.jetbrains.com.cn:443 -showcerts 查看证书链。

    然而令人震惊的是，时隔这么长时间居然都没有修复。

    尽管如此，只要不依赖新版证书就可以访问，例如系统内置 curl，或者指定新版 curl 使用系统内置证书 SSL_CERT_FILE=/etc/ssl/cert.pem，或者直接信任该域名。以下介绍几种解决办法：

    1. 首先当然可以让 brew 临时使用系统内置 curl（版本不能太新）。但是我的内置 curl 有点古老，不支持目前一些服务器已经要求的 TLS 1.3，每次切回去也麻烦。

    2. 把 download.jetbrains.com 加入代理，自动重定向到境外服务器，就不会跳转到 download.clf.jetbrains.com.cn 了。

    3. 先让 brew 安装，获取 URL 和缓存路径，用 curl 手动下载文件，然后重新安装即可：

    4. 直接信任该域名证书链。

      设置环境变量 HOMEBREW_FORCE_BREWED_CA_CERTIFICATES=1，这会让 curl 读取 $(brew --prefix)/etc/ca-certificates/cert.pem 文件以及同目录下的证书。brew 调用 curl 实际上执行的是一个包装脚本，位于 $(brew --repository)/Library/Homebrew/shims/shared/curl，它里面有证书相关的细节。

      然后运行以下脚本将证书下载到该目录下：

      domain=download.clf.jetbrains.com.cn
cert=$(brew --prefix)/etc/ca-certificates/$domain.pem
openssl s_client -connect $domain:443 -showcerts </dev/null |
  awk '/-----BEGIN CERTIFICATE-----/{flag=1} flag{print} /-----END CERTIFICATE-----/{flag=0}' \
  >"$cert"
ln -s $(basename $cert) $(brew --prefix)/etc/ca-certificates/$(openssl x509 -noout -hash -in $cert).0

      现在 brew 已经可以正常下载了。

    编译 Go 项目超时

    众所周知，国内网络环境编译 Go 项目会超时，只要设置国内镜像即可：

    1
2

    export GO111MODULE=on
export GOPROXY=https://goproxy.cn,direct

    我想了十天十夜也不明白，源码服务器也要屏蔽？多少有点脑瘫哦。

    继续查阅源码可知 git 从 2.48 就开始要求 perl 5.26 了。

    Catalina 自带的 /usr/bin/perl 只有 5.18，brew 编译 git 时并不使用 brew 版 perl，而是系统自带，于是我这个 Catalina 老同志就被偷袭了。

    如果指定较新的 perl export PERL_PATH=/usr/local/bin/perl，就可以正常编译。

    对此，考虑以下几种解决方法：

    1. 如果不追求新版，可以 pin 在 2.47.1。

      如果还没有用 brew 安装 git，本地有 homebrew-core 源码的话，可以提取历史版本并编译：

      1
2
3

      git show aecf26f53d0:Formula/g/git.rb >git.rb

rm ./git.rb

      或者去官方仓库下载历史版本。

      brew 脚本我认为是有 bug 的，它编译出的 git-credential-netrc 中模块路径错误，用的是编译时的临时目录，例如 /private/tmp/git-20250527-25582-blyz61/git-2.49.0/.brew_home/share/perl5。

      如果不需要 git-credential-netrc，可以将相关脚本注释掉。或者参考方法 3 修改路径。

    2. 如果想升级 git，可以将脚本中与 perl 相关部分注释掉，包括 git-credential-netrc、diff-highlight、git-send-email 相关代码，以及 Net::SMTP::SSL 模块（git-send-email 依赖它）。这也意味着这些工具将无法使用。

      git 源码中还有一个 NO_PERL 环境变量，但我没试过。

      git-credential-netrc 可能用的人不多，毕竟 macOS 上一般用 SSH、git-credential-osxkeychain。但 diff-highlight 还是很有用的，可以在 diff 高亮显示不同的部分。git-send-email 用于发送邮件。
